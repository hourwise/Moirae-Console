# Threat model

MC-00 establishes a boundary and deterministic tests; it does not claim to solve every
threat. The Fates acceptance baseline is also limited to its documented candidate, corpus,
model, and remaining containment/recovery gates.

## Residual scope

This model does not prove real Firecracker/KVM containment, guest escape resistance, host
filesystem/socket/descriptor containment, durable crash or power-loss replay behaviour, or
general safety against novel models and attacks. Those are upstream or future integration
gates, not claims made by MC-01.

| ----------------------------------------- | ------------------- | ------------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |

## MC-03 freshness/replay threats

| Threat                         | Asset                 | Trust boundary              | MC-03 mitigation                                                                                                    | Remaining limitation                                   |
| ------------------------------ | --------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Future or malformed issue time | authority validity    | Ananke → Console            | Canonical ISO timestamps are required; issue time cannot be in the future.                                          | Deployment clock synchronisation remains required      |
| Expired or overlong authority  | disclosure permission | Fates evidence → host read  | Host rejects expired/inverted receipts and enforces the 10-second maximum lifetime.                                 | Lifetime policy is demonstration-configured            |
| Exact receipt replay           | document disclosure   | authority → consuming host  | Bounded one-use Console receipt store claims before the fixture read; repeated claims return `REPLAY_REJECTED`.     | Store is not restart-persistent in this slice          |
| Repeated governed correlation  | Fates authority       | host → Ananke               | Ananke process-local replay guard rejects the canonical replay key with `CONFLICT` and no data.                     | Guard state is lost on Ananke restart                  |
| Freshness/nonce tampering      | receipt integrity     | Fates evidence → host       | `authorityReceiptDigest` covers timestamps, nonce, receipt ID, request/correlation, and decision identity.          | Digest is not a signed receipt                         |
| Synthetic fresh authority      | document disclosure   | test provider → production  | Production predicate requires Fates source, authoritative mode, receipt fields, and live transport binding.         | Synthetic mode remains available to explicit tests     |
| Cached governed response       | protected document    | host → browser/intermediary | Success and failure responses use `no-store`, `no-cache`, and `Expires: 0` controls.                                | Production proxy policy must be verified at deployment |
| URL/history receipt leakage    | authority material    | browser → host              | WebMCP input contains no receipt/nonce/expiry; the endpoint rejects extra properties and receipts never enter URLs. | Production access logs still need deployment review    |
